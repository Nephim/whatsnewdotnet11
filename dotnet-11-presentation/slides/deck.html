=====================================================================

SPEAKER NOTES: - Very common requirement in our DTOs: trimming whitespace, validating ranges, or triggering change notifications. - Previously, one simple validation check forced 6 extra lines of boilerplate. - The backing field is synthesized by Roslyn; `field` is a contextual keyword.

SLIDE 11: COLLECTION EXPRESSIONS

=====================================================================

SPEAKER NOTES: - Show how collection expressions replace ugly `new List<int>() { ... }` or `new[] { ... }`. - Highlight `params ReadOnlySpan<T>`: prior to C# 13, calling a params method allocated an array on EVERY single invocation. In hot Minimal API loops, that flooded Gen0 GC. - C# 15 `with(capacity: N)` prevents internal array resizes when initializing large collections.

SLIDE 12: ARCHITECTURE PSA - PRIMARY CONSTRUCTORS

=====================================================================

SPEAKER NOTES: - Address this directly: juniors often jump on Primary Constructors because they save lines of code. - In record types (immutable DTOs), primary constructors are fantastic. - In DI services, parameters remain mutable variables in class scope. They can be reassigned accidentally. - Our team convention: stick to explicit readonly fields for DI services.

PART 3: MODULE 3

=====================================================================

SPEAKER NOTES: - We use Dapper calling SQL stored procs. Stored procs are fast, but they often return flat tabular data. - Historically, C# devs either wrote ugly GroupJoin logic or made extra DB calls. - Modern LINQ gives us SQL-equivalent join power in memory with zero allocations.

SLIDE 15: MODERN LINQ - AGGREGATIONS

=====================================================================

SPEAKER NOTES: - In high-throughput APIs, `.GroupBy()` is notoriously expensive because it builds internal buckets of elements. - `CountBy` and `AggregateBy` stream the collection and aggregate in place. - `Index()` eliminates manual `int i = 0` counters when preparing ordered lists for React tables.

=====================================================================

SLIDE 16: MODERN LINQ - OUTER JOINS

=====================================================================

SPEAKER NOTES: - Explain real-world scenario: Dapper calls `sp_GetOrderLines` and `sp_GetCatalog`. - In memory, we need to join them. - Pre-.NET 10, developers avoided LINQ left joins because `GroupJoin` + `DefaultIfEmpty` syntax was so unintuitive. - Now `LeftJoin` and `RightJoin` are standard methods on `IEnumerable<T>`.

=====================================================================

SLIDE 17: HYBRIDCACHE ARCHITECTURE

=====================================================================

SPEAKER NOTES: - This is one of the highest ROI features in modern .NET. - Explain request coalescing (atomic factory execution): if 50 requests ask for customer 1's orders at the exact same millisecond, Dapper is called once, not 50 times. - Tag-based invalidation means no more tracking separate cache keys across endpoints.

=====================================================================

SLIDE 18: SYSTEM.TEXT.JSON & REACT

=====================================================================

SPEAKER NOTES: - Connect backend C# directly to our frontend React + TypeScript stack. - In TypeScript, union types are everywhere. With C# 15 + System.Text.Json, our backend and frontend type models mirror each other 1:1. - No more writing manual serializers or untyped `any` in React hooks.

=====================================================================

SLIDE 19: GUID V7 & TIMEPROVIDER

=====================================================================

SPEAKER NOTES: - If our team uses GUID primary keys or tracking IDs in SQL Server, standard Guid.NewGuid() destroys clustering index performance. - Guid.CreateVersion7() fixes this at zero extra cost. - TimeProvider should be injected into any service that checks current time.

SLIDE 28: RUNTIME ASYNC

=====================================================================

SPEAKER NOTES: - Explain this deeply: for 12 years (since C# 5 in 2012), async was a compiler illusion. The compiler built a state machine with MoveNext() and hoisted variables. - In .NET 11, the JIT and CoreCLR runtime directly handle suspension of managed frames. - For high-volume Dapper queries, this reduces allocation pressure on every single await.

=====================================================================

SLIDE 29: DYNAMIC PGO & DATAS GC

=====================================================================

SPEAKER NOTES: - Highlight DATAS GC: in Kubernetes pods where we run small microservices on 16-core nodes, Server GC used to eat gigabytes of RAM. - With DATAS (enabled by default in .NET 10/11), memory consumption drops automatically. - Dynamic PGO means frequently executed Dapper mappings get inlined and optimized on the fly.

=====================================================================

SLIDE 30: ZERO-ALLOCATION LOOKUPS

=====================================================================

SPEAKER NOTES: - Standard Dictionary is optimized for frequent adds and removes (mutation). - In Web APIs, 95% of our lookups are read-only reference data loaded once at startup. - FrozenDictionary compiles an immutable lookup table with zero collision overhead. - SearchValues uses SIMD CPU vector instructions to validate inputs at memory bus speed.
