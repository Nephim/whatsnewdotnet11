SLIDE 8: C# 15 UNION TYPES OVERVIEW

=====================================================================

SPEAKER NOTES: - Emphasize that unions are a general-purpose modeling tool, not just for error handling. - In domain modeling, instead of having a single class with 10 nullable properties (`TrackingNumber?`, `CancellationReason?`, `TransactionId?`) and guessing which ones are populated, each state is its own record in the union. - When you pattern-match over the union, the compiler ensures every case is handled.

SLIDE 10: THE FIELD KEYWORD

=====================================================================

SPEAKER NOTES: - Whenever we needed to trim strings, normalize casing, or guard against negative numbers on a DTO property, we previously had to write a private field and expand both `get` and `set`. - Also note the encapsulation benefit: with a manual `_sku` field, other methods inside the class could accidentally write to `_sku` directly and bypass the setter logic. With `field`, the backing field is scoped strictly to the property accessors.

SLIDE 11: COLLECTION EXPRESSIONS & NULL-CONDITIONAL ASSIGNMENT

=====================================================================

SPEAKER NOTES: - Collection expressions `[..]` are one of the highest-frequency syntax improvements in C# 12+: empty collections are simply `[]`, and merging lists uses `[.. listA, .. listB]`. - In C# 14 (.NET 10), `?.` can now appear on the left-hand side of an assignment (`activeOrder?.Status = "Processed"`).

SLIDE 14: MODERN LINQ AGGREGATIONS

SLIDE 15: MODERN LINQ OUTER JOINS

=====================================================================

SPEAKER NOTES: - Previously, writing a left outer join in LINQ required `GroupJoin` + `SelectMany` + `DefaultIfEmpty()`, which nobody could write from memory. - In .NET 10, `LeftJoin` and `RightJoin` are standard LINQ methods with the exact same parameter order as `Join`.

=====================================================================

SLIDE 16: LEFTJOIN COMPOSITE KEYS & CAPABILITIES + DEMO 05

=====================================================================

SPEAKER NOTES: - Explain how multi-column joins work in LINQ: C# anonymous types override `Equals` and `GetHashCode` across all their properties, so `new { order.TenantId, order.Sku }` acts as a composite hash key in `LeftJoin`. - Also be clear about the limitation: like `Enumerable.Join`, `LeftJoin` is a hash equi-join (it only matches `keyA == keyB`), so range joins (`BETWEEN`, `<`, `>`) belong in SQL. - [SWITCH TO DEMO]: Run `dotnet run 05_Linq_Joins.cs`.

SLIDE 17: HYBRIDCACHE

=====================================================================

SPEAKER NOTES: - Highlight the main reason to use `HybridCache` over raw `IMemoryCache`: stampede protection (request coalescing) is built in. - If 50 requests arrive for the same uncached key at the same millisecond, your SQL or Oracle database only runs the stored procedure once. - Point out that `tags` are completely optional—only pass them if you want to evict related keys together via `RemoveByTagAsync`.

=====================================================================

SLIDE 18: SYSTEM.TEXT.JSON IMPROVEMENTS

=====================================================================

SPEAKER NOTES: - Explain specifically what JSON source generation does: instead of inspecting properties via reflection at runtime, Roslyn generates the C# serialization code during build. - Also highlight `RespectNullableAnnotations` (.NET 9+): previously, even if a C# record had `string Sku` (non-nullable), `System.Text.Json` happily deserialized `{"sku": null}` into `null`. Enabling `RespectNullableAnnotations` enforces non-nullable properties during deserialization. - On union/polymorphic JSON: useful for nested polymorphic fields inside a DTO, whereas for endpoint responses we should return consistent DTO shapes per HTTP status code rather than varying 200 OK shapes.

SLIDE 19: BONUS - OPENAPI TO REACT / VITE CODEGEN

SPEAKER NOTES: - This is a high-leverage workflow improvement for our stack. - Because Minimal APIs with `TypedResults` generate an accurate `openapi/v1.json` document automatically, the React/Vite frontend can generate `schema.d.ts` from it (or use `orval` if we want generated TanStack Query hooks). - We never have to manually write `interface OrderDto` in TypeScript again, and return types match what the backend actually sends.

SLIDE 23: MODEL VALIDATION & IASYNCVALIDATABLEOBJECT

=====================================================================

SPEAKER NOTES: - Highlight the architectural point first: if you write `if (req.Quantity <= 0)` inside your `MapPost` lambda, someone will inevitably forget to copy that check into `MapPut` or a background job. - Putting data annotations and `IAsyncValidatableObject` on `OrderUpsertModel` keeps the invariant in one place for both inserts and updates. - In .NET 10, Minimal APIs gained built-in `AddValidation()` (using a compile-time source generator via `[ValidatableType]`), and .NET 11 adds `IAsyncValidatableObject` so custom validation can `await` database checks cleanly.

=====================================================================

SLIDE 24: TYPEDRESULTS & BUILT-IN OPENAPI 3.2

=====================================================================

SPEAKER NOTES: - Show how `Task<Results<Ok<IEnumerable<OrderDto>>, NotFound<string>>>` does two things at once: 1. The C# compiler verifies your endpoint only returns those declared status types. 2. Built-in OpenAPI reads that return type and populates the `200` and `404` schemas in `/openapi/v1.json` without needing `[ProducesResponseType]` attributes.

=====================================================================

SLIDE 25: OPTIONS PATTERN ENHANCEMENTS

=====================================================================

SPEAKER NOTES: - Without `ValidateOnStart()`, a missing or invalid setting in `appsettings.json` isn't noticed until a user hits the specific code path that resolves `IOptions<OrderProcessingOptions>`. - Adding `[ValidateObjectMembers]` and `[ValidateEnumeratedItems]` ensures validation also traverses nested objects and lists, and source-generated `[OptionsValidator]` makes it reflection-free.

SLIDE 28: RUNTIME ASYNC

=====================================================================

SPEAKER NOTES: - Explain why this matters to every developer on the team even if we don't have extreme throughput requirements: 1. Stack traces in logs and the Visual Studio debugger are much cleaner because the compiler state machine (`<Method>d__MoveNext`) is gone. 2. Every `await connection.QueryAsync()` in Dapper and every async Minimal API handler runs with less state-machine boxing overhead automatically—with zero code changes required.
